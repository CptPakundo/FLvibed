# NeuroNet windows: what each really is (read-only research, 7 Nov 2026, no game run)
Paths relative to FLvibed. Standing: G verified in game (doc), D dump, X decompiled (Ghidra, Freelancer.exe HDE 0.7.1, not run), C FLvibed code, U unverified.
RE = docs\FREELANCER_RE.md; dumps = research\evidence\controller_ui\hud2x_dumps\nn_nn_*_space.dumpui.txt.

## 0. Common
- Manager command to root name (X, NNWindowClose 0x45CFxx and 0x45D210): 0x63 NeuroNetNavMap, 0x65 NN_PlayerInfo, 0x66 NN_Inventory, 0x67 NeuroNetStoryStar, 0x68 ChatControl, 0x69 NN_GroupControl, 0x6A NN_Help. Open window = manager +0x3A8, command +0x3AC (RE:1145, core\game\nnwin.h). Chat/Group slots are 0 in single player.
- Windows are rebuilt at each open (modules\hud\docs\UI_HUD2_INPUTS.md:106, G). Each sits under a hidden NN<name>Button under NN_MainButton (RE:1142, G). Art: CHAR_infowindow.cmp for log/status/info, INV_biginforcard.cmp for inventory (RE:1518).
- Control kinds by vtable (dumps): 0x5E15F4 icon button, 0x5E614C / 0x5E622C text or wire button, 0x5E4F24 text, 0x5E476C rich text, 0x5E4D7C static image, 0x5E55AC scroll bar, 0x5E1764 toggle, 0x5E1924 bar (ItemDamage), 0x5E4BCC ship view, 0x5E501C edit field.
- The NN key handler 0x45CAE0 returns 0 (refuses open / close / switch) while the pause count 0x667D54 > 0 (X: 0x45CAE0 and 0x45A740 call 0x42D730).

## 1. LOG = NeuroNetStoryStar (vt 0x5D5B74; init 0x4BB810)
- Tree (dumps nn_neuronetstorystar_space; X init): StoryStarCloseButton (icon, hint 1033), StoryStarTitle (text, IDS 0x610 "NEURAL NET LOG - EDISON TRENT" in SP, 0x62F in MP), StoryStarHistoryText (rich text 0x5E476C) with child ScrollV_n, MissionButton / LogButton (wire text buttons, hints 803 / 804) with MissionText / LogText (IDS 1576 MISSION, 1577 LOG). Death mode (same class, hud2x_inventory.md:304) adds LoadAutosaveButton, LoadSavegameButton, MainMenuButton and their texts.
- Tabs (X 0x4BBFB0, 0x4BC2A0): byte +0x37C. 0 = LOG tab: entries whose text starts with an asterisk, prefix IDS 1596 "PERSONAL ENTRY:". 1 = MISSION tab: other entries, prefix IDS 1574 "OBJECTIVE:", the entry equal to a ClientObjective(i) gets another style (0x3D0A); empty list: IDS 1039 "No Mission Information". It opens on LOG when RouteList (0x672328) is empty (SP, not death), else MISSION (meaning of RouteList: unverified).
- DATA: global list head 0x672334, count 0x672338; node +8 is a FmtStr (X 0x4BA2A0 adds, 0x4BA0F0 saves). Text of a node = exe 0x4BA860 (FmtStr to wchar; a sibling of exe::FmtStrFormat 0x41C970, not the same). Entries are saved to the server with PackMissionLogData (server vt+0x130). Objectives: exe::ClientObjective 0x4C4FF0, count 0x4C4FB0 (RE:2260; reader hudinfo::ObjectiveLine, core\host\events.cpp).
- FLvibed reader without the control: none for the log list. It could walk 0x672334 and format node+8 with 0x4BA860 (neither is in flexe.h; no signature). Not established: node layout beyond +8 (node[3] == 0x723 and 0x549C are special ids), entry cap. Probe: sigtool the two globals, dump formatted entries.
- Actions: MissionButton / LogButton (click by name; pad padbases.cpp:1535-1541, D-pad L/R when the strip stands), StoryStarCloseButton, ScrollV_n. No per-entry select.
- Skin today: plate "log" (core\ui\winplates.cpp:258), window grown 0.15 H (windowtext.cpp:164; UI_HUD2_SKIN.md:586), row 40 done. Pad prompts padbases.cpp:725-731.
- Hard to replace: the rich-text box and its scroll; the text itself is readable, so a HUD 2 list is easy once the reader exists.

## 6. NeuroNet pause (MAP_PLAN.md:116), all decompiled, nothing run
- FrameUpdate 0x5B2890: Timing::UpdateGlobalTime(dt) only when not paused; UI update 0x59E080 always; the server connection object [0x67ECD0] vt+0x2C() and vt+0x30(dt) only when not paused (vt+0x30 = the server ElapseTime is unverified; RE:92 says Server.dll ElapseTime takes the frame dt 0x667D40).
- Space world update 0x54B000: GamePaused gate 1 wraps object updates 0x541380 (vt 0x174 per object), AnimDB::Update, PhySys::Update, beams 0x540BD0, collisions 0x52FC20, tradelane 0x5135B0, GameOption 0x18 block (0x538390, 0x537C30), docking state 0x54B230, vt+0x6C of the object at this+0xBA0, StarSys update 0x554EB0, texture / matanim 0x41B2E0. Gate 2 wraps 0x541580 (remote physics, MP only). Not gated: UiRender 0x59E300 and the UI, MouseSteer 0x4C7CB0 (its inner 0x4C8680 is gated), loading 0x54A940, render. The HUD block 0x412360 is skipped when 0x42D730.
- Other GamePaused (0x42D740) callers (13 in all): 0x4BB390, 0x4BB680, 0x4BC990 (mission-message / banner UI), 0x4C8680, 0x4CD9D0, 0x4D0490, 0x4F8A20, 0x4F9C20, 0x544D70, 0x558C10, 0x58B060 (text typing), 0x5B2890. FLvibed also calls it: core\game\coreframe.cpp:324,366,481,497,512; modules\controller\src\impl\controller.cpp:146,211; modules\hud\src\hud2.cpp:720; hudvis.cpp:1009-1015.
- The game pause 0x42D6F0(bool): count 0x667D54 +-1; at 0 to 1 in SP also 0x428550 (vt+0x68 on each entry of list 0x667C70 = the sound instances; 0x428040 is the per-frame sound update, runs always); resume 0x428580 (vt+0x6C). The NN manager refuses commands while count > 0 (section 0), which is why the pause blocks or closes the NN window.
- Workable: yes, it looks workable without touching 0x667D54: hook GamePaused 0x42D740 (cdecl bool, 27 bytes, flexe.h:70) and answer true by return address only to the world callers (0x54B000 x2, 0x5B2890 x2, 0x558C10, 0x544D70, 0x4CD9D0, 0x4D0490, 0x4F8A20, 0x4F9C20, 0x4C8680) and false to the UI ones (0x4BB390, 0x4BB680, 0x4BC990, 0x58B060). The NN manager reads 0x42D730, a different function, left alone. FLvibed own fl::GamePaused calls go through the same detour and need a defined answer (decide: the real count, so its autopilot keeps flying, or the hooked one).
- Keeps running: UI, sounds (voices, engine, ambient; call 0x428550 / 0x428580 for a sound pause), dt (the game dt runs through a pause, RE:91), anything on wall time: server clock (pub::GetTime), Timing::read damage stamps, audio-gated comm triggers (docs\research\IDEAS.md T2 line). If the 0x5B2890 gates are included the in-process server stops (Cnd_Timer, mission scripts, NPC AI, shields use dt); if left out the server runs on while the client world stands still: desync risk (unverified). Docking, undock and tradelane freeze mid-sequence (0x54B230, 0x5135B0). MP unaffected (GamePaused is false there).
- Probe: hook, open a window, read an NPC position and a script event over 10 s, run debug timing (RE:92), check sounds and autopilot.
