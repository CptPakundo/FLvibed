## Findings (agent report of 21 Oct 2026)

### 1 Summary
- Crossfire is the longest-running Freelancer mod: 1.0 on 8 Oct 2004, 1.7 (2007), 1.8 "Inner Core" (2010), 1.82 (2010), 1.9 "Dark Ages" (2011, first real SP campaign: 21 missions), 2.0 (beta 2014, release Oct 2015, 43-45 new missions), 2.0.1 re-release 15 Nov 2020 (standalone installer, no FLMM), weekly launcher updates since 2022, "2.0.2" installer announced for 2026. One author (SWAT_OP-R8R), one official server, proprietary EULA (no modification, no redistribution).
- It is a data mod plus a plugin stack: it ships the official v1.1 Common.dll/Server.dll/DALib.dll/RemoteClient.dll/flserver.exe (PE builds of 21 May 2003, debug overlay intact), a content.dll with a 4-byte constant patch (plus a 2-byte call redirect for OpenSP), and 50+ plugin DLLs in `EXE\dacom.ini [Libraries]` (33 of adoxa's, plus its own DSAce.dll anticheat, dExchange32.dll, KeyMapping.dll, MultiUniverse.dll, libcurl). It does **not** ship a game Freelancer.exe: `EXE\Freelancer.exe` is the Qt launcher (v2.3.0.0); the game runs from a launcher-built `EXE2\` copy of the user's vanilla v1.0 exe (installer demands FileVersion 1.0.1223.11).
- The whole 30-mission Crossfire campaign lives inside **`DATA\MISSIONS\M13\m13.ini` (892 KB, 1,525 triggers)** - the story state never leaves `Mission_13`; new content uses `Act_Save = mission14save..mission29save`, 43 new THN cutscenes (`DATA\SCRIPTS\STORY\cf1..cf43.thn`) and string ids in extra resource DLLs (sol.dll, respawn*.dll, news.dll, storyaddon.dll).
- "New voice samples" = three robot voice banks (`timer.utf`, `timerfemale.utf`, `timerdk.utf`, ids `dx_m13_CFmission01..43` declared in voices_mission12.ini), 4 new recorded clips (3 Orillion, 1 Trent), and heavy reuse of vanilla lines (DX_M01..M12 ids spoken out of context by Juni/King). No subtitles anywhere; players ask why the vanilla subtitles "disappeared".
- Widescreen: an installer option swaps jflp.dll builds, loads `jflp.dll nofovx`, HudShift auto, 16:9 HUD texture sets, Cameras.ini fovx=0, THN camera variants for base rooms (`WSfix`), a `CFWidescreenfix.exe` tool; movies via `[Startup]` (SWAT logo + intro + 320 MB CF intro, or 20 KB blanks to skip). No controller/joystick work at all (keymap.ini has 0 joystick lines).
- For FLvibed: nothing collides by design (the adoxa plugins are the HDE ones plus more), but (a) the game runs in `EXE2\` under a launcher that hash-verifies files and (in MP) an anticheat that enumerates modules - an injected DLL is a ban risk; (b) KeyMapping.dll / dExchange32.dll / DSAce.dll patch memory with unknown targets (packed); (c) story-state logic that assumes `Mission_13` = the finale breaks; (d) MultiCruise (per-engine cruise speed), MultiUniverse, storylvl gates of 80k-1.2M credits, MatchPlayer are data the autopilot must read, not assume.

#### 3.3 Campaign extension mechanics
- Directory layout is vanilla: `DATA\MISSIONS\M01a..M13` only; every vanilla mission has an `opensp*` twin (ini + thn) [file]. ### 4 Relevance to FLvibed

### Actionable (concrete)
1. **Install path and launcher.** Under Crossfire the game process is `<CF>\EXE2\Freelancer.exe`, started by the Qt launcher, with `EXE2\dacom.ini` rebuilt/verified from `EXE\` ("Verify game file hashs", update.dat). FLvibed's installer must target `EXE2\` and expect the launcher to overwrite or flag edits; treat `EXE2` as a first-class install location in `tools\install` / `docs\MOD_COMPATIBILITY.md` [file].
2. **Anticheat = ban risk in MP, false positives in SP.** `DSAce.dll` is packed and enumerates process modules (`GetModuleFileNameExA`) and the MAC (`GetAdaptersInfo`); `CheatMessage.txt` exists; MP autobans happened for unexplained reasons (Jan 2021 thread). FLvibed should default to **not loading when DSAce.dll is present and the client is in MP** (or at least warn), and never be presented as MP-safe on Crossfire's server [file + page]. SP: the forum says anticheat also runs in SP; FLvibed.dll in the module list is a plausible trigger [assumed].
3. **Hook-family collisions.** The adoxa set is HDE's plus more; all are detour/IAT-style plugins FLvibed already chains with. New risks: `KeyMapping.dll` (SP-only WriteProcessMemory patch, probably in the key dispatch area FLvibed detours: `HandleKey 0x576410`, `IsCmdHeld 0x5784A0`, `WinKey 0x577850`) - FLvibed's signature check must **fail closed per symbol** and the controller module should log which symbols failed; `dExchange32.dll` (packed, `Timing::GetGlobalTime`) may hook the frame/time path (`FrameUpdate 0x5B2890`) [assumed]; `HudShift` (already handled), `TurretZoom max=1000 switch=0`, `GaugeCol`, `numeric`, `scroller`, `Zone`, `Territory`, `names`, `NoNavMap`, `ShipRange`, `MultiIntro` touch HUD/UI code FLvibed reads (`UiRender`, `ManeuverLayout`, HUD position constants) - run the signature table against a Crossfire `EXE2\Freelancer.exe` once a user can supply one (the installer does not contain it) [file].
4. **Game exe version.** The installer requires a v1.0 exe (1.0.1223.11) while shipping v1.1 DLLs; what runs in `EXE2` is launcher-managed. FLvibed's `flexe.h` signatures are for the 1.1 exe as shipped by HDE; expect either a 1.1 exe (signatures hold) or a 1.0 exe (most addresses shift; everything fails closed). Add a startup log line with the exe's FileVersion and a clear "unsupported exe" message [file + assumed].
5. **Story-state logic.** FLvibed must not treat `Mission_13` as "the finale": under Crossfire the state stays `Mission_13` for 30+ further missions; mission identity comes from `Act_Save` names (`mission14save`...), `Act_SetTitle` ids (sol.dll, index 7) and the save's `[TriggerSave]`. Mission runbooks keyed by `Mxx` do not apply; the autopilot's generic rules (objectives, marks, comms) do - exactly the "one mechanism from the game's own data" principle [file].
6. **Data FLvibed must read instead of assuming (autopilot):** `MultiCruise.dll` (per-engine cruise speed - read the engine's cruise speed / measured speed rather than 300), `storylvl.ini` gates of 80k-1.2M (the `worth-target` event already carries the game's value - keep that path), `MatchPlayerCF` (NPC rank follows the player: combat odds change), `healing` (negative-damage zones/weapons = repair), `ShieldOffline`, `ammolimit` (per-ammo caps for consumable planning), `RandomJumps`/`JumpOutPt`/`dock_key`/`moors`/`LaneSpeed`/`EquipMass` (already in MOD_COMPATIBILITY), `MultiUniverse` (universe swapped per mode - kb generated tables must be regenerated for the Crossfire install; `tools\kbgen.ps1 -Check` fingerprint), 55 `Act_Cloak` uses (cloaked story ships: target lists change), `Act_Popupdialog` 109x and `Act_SetOffer` 90x (bar-offer gating the autopilot must notice via the pub:: IAT hooks it already has) [file].
7. **Subtitles.** Crossfire's new lines are (a) three robot voice banks with 43+ ids `dx_m13_CFmission*`, (b) 4 recorded wavs, (c) vanilla ids replayed out of context. FLvibed's FindVoice/PlayArch hooks will see vanilla ids (text already exists) and unknown ids (no text). Design: keep the per-id lookup, show nothing for unknown ids (fail closed), and consider a later "foreign voice bank" path taking a mod-supplied TSV keyed by msg id (the bank/msg -> CreateID mapping in FREELANCER_RE.md already covers `extend =` banks) [file]. Copyright: Crossfire's EULA forbids derived works - FLvibed must not ship transcripts of Crossfire's lines without permission.
8. **Movies.** Crossfire keeps the `[Startup] movie_file` mechanism (three files, blank 20 KB wmv to skip): FLvibed's Movie.dll `IBasicVideo` fitting applies unchanged; the subtitled-intro table should key on file name + duration so the SWAT logo and the CF intro simply get no subtitles [file].
9. **Widescreen.** Crossfire loads `jflp.dll nofovx` and sets `fovx = 0`; FLvibed's `CinematicAspect`/letterbox math reads the live value (good) - verify the `nofovx` case on a 16:9 Crossfire install before claiming support; `HudShift Horizontal = auto` is the HDE case already handled [file].
10. **Compatibility doc entries to add** (`docs\MOD_COMPATIBILITY.md`): Crossfire section with the plugin list above, the `EXE2` layout, the anticheat caveat, the content.dll variants (sp/opensp/mp), and "not tested; signatures unverified because the exe is not distributed" [file].

### Ideas to borrow
- Installer that copies the vanilla game aside (`CopyVanillaFL`) and refuses non-clean installs with a clear FileVersion gate and human message.
- Launcher-side file hashing (`SRV HASH` vs `CUR HASH`) to self-heal an install - for FLvibed: a manifest with hashes of its own deployed files to detect partial installs (Robustness).
- Options as component swaps (HUD colour sets, cursor sets, colour-blind reticles, intro choices, skip-movies via blank files): FLvibed's planned toggles/presets could ship HUD cue palettes and a colour-blind option as data, not code.
- No-HUD toggle tool and turret-zoom modifier steps (Shift/Ctrl/Alt) are UX conventions worth matching on the pad (chorded steps).
- Story-as-single-script with save names and title ids shows a campaign can be extended without new Content.dll states; FLvibed's harness should identify a mission by the last `Act_Save` nickname / title id - the general mechanism, which also works for Crossfire.

### Theoretical
- A generic "mission timeline" view derived from any `m*.ini` (triggers -> saves -> titles) would let the autopilot and the subtitles tool map unknown campaigns (Crossfire, Nomad Legacy, Co-op campaign mod) without runbooks; the extractor already produced the counts for Crossfire.
- Crossfire's robot "timer" voice banks are effectively TTS narration; a FLvibed "text-only comm" renderer could serve mods that have text but no voice.
- The anticheat affinity trick (resetting process affinity on dock/undock) is a reminder that other plugins change process-level state; FLvibed should never assume thread/affinity state and should log such changes when detected.
