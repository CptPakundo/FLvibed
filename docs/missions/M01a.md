transport convoy from Manhattan to Pittsburgh (Fort Bush trade lanes), with an Order ambush at the start and a pirate
ambush at a broken trade lane. It teaches combat, trade lanes, formation and docking, and it is full of fail timers.

**Conventions**

- Line numbers are 1-based, as an editor and the Read tool show them (`[Mission]` is line 1). A trigger's number may
  point at the line inside it that matters (e.g. `king_dies` 254 = its `Cnd_Destroyed` line).
- `->` = "activates" (`Act_ActTrig`). `DeactTrig` = `Act_DeactTrig`.
- Times are seconds. `Cnd_Timer` values are added up along a chain. A comm line (`Act_SendComm` / `Act_EtherComm` / `Act_StartDialog`) has the duration in the `sec` column of `subtitles\data\subtitles.tsv`. Where a chain waits for a line (`Cnd_CommComplete`) the line's seconds are added. I assume that queued comms and the lines of one dialog play back to back with no gap (**Uncertain**). A `Cnd_Timer` that is armed in the same tick as a comm starts at the same moment as the comm; it does not wait for it. Real seconds are marked `s`.
- Names: `T0` = the tick of `spe_initialize_end` (SpaceEnter in Li01). `D` = tick of `d_order` (step 5). `P` = tick of `pirates_end` (step 14).
- Ids such as `21810` are text-table ids. Titles are resolved from `research\strings\resources.tsv`; long texts are not copied. A popup is written as caption id + text id (`21895`/`21945`); the harness event shows the caption.
- Comm events carry only `first=0x<hash>` of the first line: `Get-FLHash 'DX_M01_0100_KING'` (`tools\flhash.ps1`) gives the value to match. This runbook names the line by its `DX_` id.
- Triggers without `InitState` are treated as inactive until something activates them. This matches how the file uses `InitState = ACTIVE` (lines 451, 774).
- Only `Act_ChangeState` changes the mission outcome directly. ~~Nags (`Act_Nag*`) are treated as messages only~~ **Superseded by the verified correction above:** several nags carry a FAIL text (table below) and `gopittslate` is verified to fail. Treat every nag in this file as a fail path until tested.
- `Cnd_WatchTrigger = X, ON` is read as "trigger X is still armed (has not fired)", `OFF` as "X has fired or was deactivated". This is an inference (**Uncertain 11**), supported by the texts of `wt_u_bad1_on` (King: "re-enter formation") and `wt_chk0380_on`. It changes the earlier reading of steps 10, 11, 14, 15, 16.
- Harness: `Close-FLBlocker` clicks `MMOkButton` (every `Act_Popupdialog`) and `NavMapContinueButton` (mission briefing). It does not handle the offer dialog (`click OfferDialogAcceptButton`), base room scenes (`Skip-FLAnimation`, default in `Load-FLSave` / `Goto-FLRoom` / `Start-FLLaunch`), space cutscenes (`Wait-FLSpace` waits them out; never send Escape in space), or the death dialog. Every wait in a mission step should loop `Close-FLBlocker` (the popups pause the game).
