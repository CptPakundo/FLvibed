**Conventions:** line numbers are 1-based (as an editor and the Read tool show them). A line number after a trigger name is its `nickname =` line. `->` = `Act_ActTrig`. Times are seconds. Comm events carry `first=0x<Get-FLHash of the DX_ id of the first line>` (verified); I name the line by its number, e.g. `1060` = `dx_m10_1060_hakkera`. `+lines` = comm line durations, taken from the `sec` column of `subtitles\data\subtitles.tsv`. Text ids are resolved from `research\strings\resources.tsv` (titles only). Triggers without `InitState` start inactive. Only `key_to_start_init` (3153) has `InitState = ACTIVE`.

**Nags are fails.** Every nag in this file (`Act_NagDistTowards`, `Act_NagDistLeaving`) carries a text id that is exactly a "Mission Failed. ..." text (23957, 23960, 23962, 23967, 23970, 23972, 23975, 23977, 23980, 23982). As verified in M01a, a nag that runs out escalates to FAIL with that text. So each nag below is a fail path. Nag timing is engine-defined, not in the file (**Uncertain**, no seconds given).

The M09 runbook ends in Kyoto Base after its SUCCEED. This script has no hand-over trigger: `key_to_start_init` (3153, `system = Ku06`) arms itself at once, so M10 is open whenever the player is in Ku06.
