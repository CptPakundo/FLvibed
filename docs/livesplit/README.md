# LiveSplit and speedrun mode (FLvibed, 25 Oct 2026)

Two things live here: the **LiveSplit splits files** (`<leg>.lss`, generated by `tools\splits.py lss` from
`docs\checkpoints.tsv` with the comparisons par / WR run / runners' best segments / our PB and our gold as best
segments - open one in LiveSplit to see a leg as the runners do) and **what the mod itself does in speedrun mode**
(`controller\src\impl\livesplit.cpp`, `runtimer.cpp`, `newgame.cpp`; design `docs\UI_PLAN.md` 6.6; settings under
AUTOPILOT > SPEEDRUN MODE: `speedrun_timer`, `livesplit`, `livesplit_port`, `livesplit_gametime`). The mod never calls its
timer official: speedrun.com times Freelancer in real time by hand.

## Speedrun mode per save
NEW GAME on the pad opens FLvibed's prompt NORMAL GAME / ASSISTED / SPEEDRUN MODE. The choice is recorded without
touching a game file: `EXE\FLvibed\saves.ini` (`<save file> = <mode> <clock ms> <checkpoint index>`), one line per save
file the game wrote during a session of that mode (its Act_Save checkpoints, the autosave, the player's saves - a folder
change notification, no polling). A loaded save's line sets the session's mode (ASSISTED = `ap preset competent`,
SPEEDRUN = `ap preset speedrun` + the timer + LiveSplit); a save without a line is NORMAL. Which save loaded is read
from the load screen's selected row (the game's own field) when the game leaves the menu, or `AutoSave.fl` after the
death dialog's LOAD AUTOSAVE. The load screens show a tag ASSISTED / SPEEDRUN over such rows.

## The clock
Game time since the New Game click: wall time while the game is not in its menu (loads excluded; the F1 pause counts, as
real time does). Carried per save in `saves.ini` and restored with the save. Shown by the HUD timer top right under the
NeuroNet box (h:mm:ss.t, the next checkpoint's name, after a split the segment's delta against the player's best segment
in `EXE\FLvibed\splits_best.ini`, green / red; while a segment runs, the live delta once it is behind the best).

## The split detector (the same checkpoints and conditions as `tools\splits.py`)
`controller\src\impl\checkpoints_gen.h` is generated from `docs\checkpoints.tsv` by `tools\checkpoints_gen.py`
(`--check` for the drift check): 193 rows over the 14 legs, in story order. The detector keeps the index of the last
checkpoint reached and matches live observations against the next row (`ours` column):

| `ours` | live condition |
|---|---|
| `obj:<id>` | the objective step's text id (HostApi ObjectiveNow, entry 0 of pub::Player::SetMissionObjectives) equals `<id>`; 21660 "Awaiting Mission Objective" is ignored |
| `control` | mode cutscene / docked -> space / space-ui (the HUD back after a launch or a space scene) |
| `land` | mode -> docked from a game mode (not from the menu) |
| `launch` | mode docked -> a space mode |
| `cutscene` | mode space -> cutscene |
| `success` | the mission's result: the game's own SUCCESS mission message (HostApi v20 `MissionResult`: the client's `pub::Player::DisplayMissionMessage` of the success kinds, the same `mission-message type=SUCCESS text=1231 "Mission Result: Success"` every full PASS log ends in), and only while the next row is the leg's success row. With an older host (no v20) the fallback: the objective list cleared TWICE in one instant (two SetMissionObjectives count 0 at the SUCCESS message's millisecond in every full PASS log of the 14 legs; a script's mid-mission clear - M03 after the Willard battle, M04 at the Magellan gate, a save's load - is a single call) |
| `kill:<n>` | the n-th marked solar (MissionMarks, ids above 100000, same system) that is no longer among the client's objects (space::Contacts) since the leg's first row |

Verified offline (25 Oct 2026): the newest full PASS log of every leg replayed through a mirror of these rules against
`splits.py our_splits` agrees on 193 of 193 checkpoints (the scratch replay; kills from the logs' target-destroyed
events, live from the marked solars vanishing - the live kill path was seen firing once on the M12.banner save).

Rules shared with splits.py: one split per row, in order, never twice; an objective up to 5 s before the previous
checkpoint counts at that checkpoint's time (LOOKBACK); a missed `obj` / `kill` row is skipped (split at the same time)
when a later objective row's exact id shows within three rows; the mode kinds match only the very next row. A loaded
save restores its row index from `saves.ini` (a save without one starts at -1 and syncs on the first exact objective
id). The final row (M13.end, `land` into the Dyson sphere's city) is the story's end.

## LiveSplit Server (TCP)
A non-blocking client to 127.0.0.1:`livesplit_port` (16834; LiveSplit 1.8.29+: Control > Start TCP Server), each
command line-terminated with `\r\n`; reconnects with a backoff (2 s doubling to 30 s), never blocks a frame; commands
sent while disconnected are dropped and logged. The client connects only while a speedrun session runs (from the New
Game click or a speedrun save's load until the main menu; a command sent while the connection is being made waits up
to 6 s for it) or while the debug `livesplit connect` / `test` asked; `livesplit` 1 alone opens no socket (25 Oct 2026). `starttimer` on the New Game click in speedrun mode; `split` per
checkpoint and at the story's end; `reset` when the main menu shows; `pausegametime` / `unpausegametime` entering /
leaving the menu (loads) when `livesplit_gametime` is on. LiveSplit's own timer is started only by New Game: a loaded
speedrun save gets splits but no `starttimer` (the player's LiveSplit may already run). Debug: `livesplit state|test
[cmd]|connect|reset|start|event <kind> [v]|rows|cp <n>`, `timer state|bests|reset-best`, `newgame state|records|mode <n>`.

## `FLvibedSplits`: the memory struct for autosplitters
An exported plain global `FLvibedSplits` (in `FLvibed.dll`; `FLControllerImpl.dll` in the dev build), found through the
export table or by a scan for its magic. Little-endian, 4-byte fields, fixed layout; version 1:

| offset | type | field |
|---|---|---|
| 0 | char[8] | `magic` = "FLVSPLIT" |
| 8 | u32 | `version` = 1 |
| 12 | u32 | `size` = 112 (sizeof) |
| 16 | u32 | `mode` 0 normal, 1 assisted, 2 speedrun, 0xFFFFFFFF none |
| 20 | u32 | `running` 1 while the clock counts |
| 24 | u32 | `runTimeMs` game time since New Game, loads excluded |
| 28 | i32 | `checkpointIndex` last reached (-1 none), row of checkpoints.tsv |
| 32 | u32 | `checkpointCount` (193) |
| 36 | u32 | `splitSeq` grows with every split |
| 40 | u32 | `lastSplitMs` |
| 44 | u32 | `inMenu` 1 in the menu (game time paused) |
| 48 | u32 | `realTimeMs` wall time since New Game |
| 52 | char[32] | `checkpoint` last reached, e.g. "M01a.wing" |
| 84 | char[32] | `nextCheckpoint` |

An ASL script can start on `running` 0 -> 1 with `runTimeMs` 0, split on `splitSeq` changes, reset on `mode` 0xFFFFFFFF,
and use `runTimeMs` as game time.
